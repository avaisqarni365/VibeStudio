# 01 Project Intake

Use this file when starting a new vibe-coding project or converting a rough idea into a professional software plan.

## Required intake fields
- Project name
- Business goal
- Target users
- Primary user roles
- Core problem
- Success criteria
- Platforms: web, mobile, desktop, API, browser extension, automation, CLI
- Tech stack preference
- Existing repo/folder link or status
- Integrations: Claude, Cursor, Codex, ChatGPT, Jira, GitHub, GitLab, VS Code, database, CRM, payments, auth
- Data sensitivity and privacy needs
- Timeline and sprint length

## Output structure
Create a `PROJECT_PLAN.md` with:
1. Executive summary
2. User roles
3. Feature list grouped into MVP, v1, later
4. Non-functional requirements
5. Engineering risks
6. Recommended repo structure
7. AI coding tool plan
8. First 10 implementation tasks

## Question strategy
Ask at most 5 questions at once. If the user is in a hurry, make sensible assumptions and mark them clearly.

## Definition of ready
A project is ready for AI coding only when it has:
- clear MVP scope
- stack decision
- target files or modules
- acceptance criteria
- testing or validation method
